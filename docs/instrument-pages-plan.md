# Страницы инструментов с анимированным музыкантом: план

Идея: у каждого инструмента своя страница с описанием (что это, как
держат, какие удары, что в нём слышит танцор), на ней живая мини-машина
с ритмом этого инструмента, выбор варианта ритма и нарисованный
персонаж, который играет вместе со звуком: бьёт сильно или слабо в
зависимости от удара и меняет манеру движения с темпом.

Статус: только план, ничего не сделано.

## Что уже есть и на что опираемся

- **Ритмы с типами ударов.** В `app/genres/*/patterns.ts` у каждой партии
  не просто «удар / пауза», а тип удара: у конги `heel`, `toe`, `slap`,
  `open`; у тимбалес `rim`, `open`, `neck`; у гуиро `long`, `short` и т. д.
  Это готовая разметка для поз персонажа.
- **Машина.** `useBeatMachine` + `TempoStepper`, `Transport`,
  `SegmentedControl` — мини-машину для одного инструмента собираем из них.
- **Синхронная анимация.** `app/core/motion.ts` и
  `app/composables/useBeatEffects.ts` уже двигают иконки инструментов
  через Web Animations API (только `transform`), по аудиочасам
  (`app/core/audio/playhead.ts`), с физическим затуханием и наложением
  ударов (`composite: 'add'`). Персонаж — тот же подход, только частей
  больше.
- **SEO-страницы.** `app/pages/[genre].vue` + `useSeoPage`, карта сайта в
  `shared/sitemap.ts`.

## Этап 1. Страница инструмента (без персонажа)

1. **Маршрут** `app/pages/[genre]/[instrument].vue` (`/salsa/conga`,
   `/ru/salsa/conga`). `validate` — жанр существует и инструмент есть в
   `genre.instruments` и в списке страниц (не у каждого инструмента сразу
   будет страница; голос `voice` — никогда).
   - Проверить, что Nuxt корректно уживается с `[genre].vue` и
     `[genre]/[instrument].vue` одновременно (обычно нужен
     `[genre]/index.vue`, тогда `[genre].vue` переносится туда).
2. **Данные страницы** — в описание жанра (`app/genres/types.ts`) добавить
   необязательное поле, например:

   ```ts
   /** Instruments that have their own page, with the rhythms it offers. */
   instrumentPages?: Record<string, InstrumentPage>

   interface InstrumentPage {
     /** Variants offered in the picker; the first one loads by default. i18n `instrumentPages.<genre>.<instrument>.variants.<id>`. */
     variants: { id: string, figure: Step[], stepsPerCount?: number }[]
     /** Plays along, quieter, under "with the band" (e.g. the clave under the conga). */
     companions?: string[]
   }
   ```

   Фигуры брать из тех же констант, что и пресеты (`TUMBAO`, `CLAVE_3_2`…),
   а не копировать — для этого экспортировать их из `patterns.ts`.
3. **Текст** — в `i18n/locales/{ru,en}.json`, ключи
   `instrumentPages.<genre>.<instrument>.{title,description,body,...}`.
   Если тексты станут длинными — перейти на markdown-файлы (Nuxt Content
   или простой импорт `?raw`), но начать с i18n.
4. **Мини-машина** — компонент `InstrumentPlayer.vue`: строит `Pattern`
   из выбранного варианта (`definePattern`) и отдаёт его в
   `useBeatMachine`. Управление: play/stop, темп (в пределах
   `genre.bpmRange`), вариант ритма, переключатель «соло / с оркестром»
   (в режиме «с оркестром» — дефолтный пресет жанра, где остальные
   дорожки тише, а этот инструмент выделен). Под машиной — строка сетки
   (`TrackRow`) только этой дорожки, чтобы было видно, что играется.
5. **Ссылки** — со страницы жанра (карточки инструментов,
   `InstrumentCards.vue` / `LayerGuide.vue`) на страницу инструмента и
   обратно. В `shared/sitemap.ts` добавить страницы инструментов
   (`tests/sitemap.test.ts` должен по-прежнему сверять с `app/genres`).
6. **Тесты**: у каждого `instrumentPages`-инструмента есть тексты на всех
   языках и хотя бы один вариант; фигура варианта использует только удары,
   для которых есть сэмплы (как уже проверяется для пресетов).

Первый инструмент — **конга** (сальса): у неё самые разные удары и
понятные варианты (полный тумбао, упрощённый — только `open` на 4 и &4,
тумбао для On2). Затем клаве (3-2 / 2-3 / румба-клаве), колокол
(мамбо / бонго), бонго (мартильо), гуиро; в бачате — бонго и гуира.

## Этап 2. Анимированный музыкант

### Рисунок

- **SVG с «костями»**: корпус, голова, у каждой руки плечо → предплечье →
  кисть отдельными вложенными `<g>` с `transform-origin` в суставе,
  инструмент — отдельный слой (его кожа/корпус качаются, как у иконок).
  Так поворот плеча тянет за собой всю руку, а удар — это поворот трёх
  групп.
- Стиль — в духе текущих иконок (линии, акцентный цвет жанра,
  `data-genre`), чтобы работала тёмная тема.
- Один базовый персонаж, разные инструменты — разные позы рук и сам
  инструмент. Если позже будет художник — тот же «скелет» (те же id
  групп) можно перерисовать, код не меняется.
- **Альтернатива — Rive** (rive.app): если персонажа будет анимировать
  дизайнер, у Rive есть машина состояний со входами («удар», «сила»,
  «темп»). Плюс — живость; минус — рантайм на WASM в несколько сотен КБ и
  внешний редактор. По умолчанию — SVG + Web Animations, без новых
  зависимостей.

### Позы и сила удара

Таблица «тип удара → движение» рядом с `motion.ts`, например
`app/core/musician.ts`:

| Удар (конга) | Рука | Замах | Отскок | Корпус |
|---|---|---|---|---|
| `slap` | открытая кисть, у края | высокий, резкий | короткий, кисть «прилипает» | подача плечом вперёд |
| `open` | пальцы у края | средний | упругий, рука отлетает | лёгкий кивок |
| `heel` | ладонь, основание | почти нет, перекат | — | — |
| `toe` | пальцы, после `heel` | почти нет, перекат | — | — |

Аналогично для остальных: палочка тимбалес (`rim` — плашмя по корпусу,
`open` — по колоколу), клаве (одна палочка бьёт по другой), гуиро
(`long` — длинный проход, `short` — короткий). Сила удара берётся из типа
удара и громкости дорожки (`Track.volume`).

Какой рукой бить — правило на инструмент (у конги `heel`/`toe` —
чередование, `slap`/`open` — ведущая рука; у гуиро — одна рука всегда).

### Зависимость от темпа

- **Замах не длиннее интервала до своего удара**: время замаха =
  `min(естественное время замаха, время с прошлого удара этой руки)`.
  На медленном темпе руки поднимаются высоко и плавно, на быстром —
  короче и ниже, как у живого музыканта.
- **Амплитуда** замаха масштабируется так же: чем меньше времени, тем
  ниже рука.
- **Корпус** покачивается на каждый счёт (`countPulse` уже есть), сильнее
  на 1 и 5; размах растёт с темпом.

### Синхронизация: замах до звука

Сейчас анимация стартует в момент звука (playhead отдаёт шаг, когда он
прозвучал), а планировщик заглядывает вперёд всего на 100 мс
(`SCHEDULE_AHEAD_S` в `app/core/audio/scheduler.ts`) — для замаха этого
мало. Решение: аниматор не ждёт будущих шагов от планировщика, а сам
смотрит в паттерн — он детерминирован. На каждом шаге, который пришёл из
playhead, аниматор знает текущий шаг и темп и вычисляет, когда будет
следующий удар этой руки, и запускает замах так, чтобы контакт пришёлся
точно на звук. Ровно в момент звука — сам удар и отскок (как сейчас у
иконок). При остановке, смене темпа или паттерна — плавный возврат в
исходную позу.

Для этого в `Beat` нужно передавать не только список инструментов, но и
что они играют: `strokes: Record<string, Step>` (правка в
`StepCallback` планировщика, `showStep` в `useBeatMachine` и
`playhead.ts`).

### Доступность и скорость

- С `prefers-reduced-motion` / выключенной анимацией (`useMotion`) —
  персонаж стоит, подсвечивается только рука, которая играет.
- Только `transform`/`opacity`, ограничение одновременных анимаций на
  часть (как `MAX_RINGING`), проверка на слабом телефоне и в Telegram
  Mini App.
